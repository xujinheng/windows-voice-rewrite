# Architecture

VoiceRewrite has native Windows (Go/Win32) and macOS (SwiftUI/AppKit with a bundled Go `voicebridge`) desktop hosts. Portable Go packages under `internal/core` contain shared processing, provider protocols, connection probing and task orchestration. Platform adapters own device access, UI, input, configuration files and OS credential storage.

## Portable core

| Package | Responsibility |
| --- | --- |
| `internal/core/audio` | Validate interleaved PCM16 formats and packet sizes; mix channels, resample to 16 kHz and assemble 20 ms mono frames; provide audio framing, voice segmentation, preview timing, transcript chunking, the shared 0.1s capture floor, a 0–1000 recording-indicator RMS level, and the `FrameSource` contract. |
| `internal/core/indicator` | Recording-pill phases, geometry, labels, opacity, waveform motion, progress-wheel beads, microphone-level gain, the shared pill colors, and the cancel choice. A pending preview wins, a stale message is ignored, and a finished phase only closes the pill. Hosts paint the window and own the microphone. |
| `internal/core/input` | Map a physical side button to dictation, rewrite, or ignore, and track one button's press, hold, and release. Windows starts recording after 250 ms. macOS starts after 280 ms. A keyboard hold and a side-button arm both refuse a paused, busy, recording, or already pending start. The keyboard hold reports a missing foreground window; a side-button arm with no window returns quietly. A side hold for another button is ignored. A hold that is no longer ready is discarded, even when the microphone also failed. A ready hold whose microphone failed closes the preview and reports the error. A ready hold activates. Confirming a side hold requires that same window. The rewrite shortcut finishes a toggle recording, starts a hold, or prepares a toggle selection. A toggle prepare that never hears the keys release reports the failure and does not restore a clipboard. A failed capture, a selection that is too long, and a microphone that does not start restore the clipboard and report the error. A generation that expires after the microphone starts restores the clipboard and stops the recorder without a status sentence. A missed UI notification stops the recorder and does not restore the clipboard. The hold watcher waits the configured maximum plus two seconds. Pill labels keep meeting dictation and meeting rewrite distinct. Hosts own the event tap or mouse hook. |
| `internal/core/shortcut` | Canonical voice hotkeys: mouse side buttons, function keys, and Ctrl/Alt/Shift combinations. Bare typing keys and Pause/Break are rejected, and two voice actions cannot share a shortcut. Startup rejects a shared side button, keyboard dictation or a side button outside hold mode, and a voice hotkey that matches exit. macOS maps the key name to its own virtual key codes. macOS settings default to Ctrl+Alt+R, Ctrl+Alt+E, and Ctrl+Alt+T. A shortcut rejection sentence is shown unchanged; other shortcut failures keep the macOS prefix. Settings capture ignores modifier keys and rejects a held Windows key before parsing. macOS Accessibility and clipboard failures use the Interaction module's status sentences. Saving a pair trims both fields, validates rewrite, then dictation, and reports whether either stored value changed. A Windows settings field error is shown before an in-progress shortcut capture. A busy voice task is still refused before the fields are read. A shortcut change or an audio-device change uses the restart notice. A settings key cancels capture, accepts the key, or closes the window. The Windows-key capture sentence is shown without the failure prefix. |
| `internal/core/desktop` | Keep a window inside a monitor work area, including monitors with negative coordinates, and center one in that area. |
| `internal/core/popup` | Result-card size for a text length, the editor, note, close, copy, and apply frames, and which clicks dismiss the card instead of the text or its buttons. A blank body is refused before the window opens, and the editor text uses Windows newlines. That refusal is not the empty-model sentence. A manual apply with no selection, a preview-only card, a canceled card, or a stale generation returns before taking the busy flag. A busy task shows the busy note and does not release the flag. A closed editor reports the editor error and releases the flag. An open editor replaces the selection. The card header is a client click, not a drag caption. |
| `internal/core/settingsform` | Logical-pixel geometry for the settings window: stretching rows, the shared field, label, and shortcut rectangles, the minimum window size, footer anchors, scroll steps, the outer window size, and the navigation, probe, note, footer, hint, capture, and microphone boxes. After scrolling, navigation stays at its design position, the footer and hint stay pinned, and the other controls move. The navigation rail, its color, and both title boxes live here. The Direct2D title box and the GDI title bounds stay different, as do the field corner radii. The hint and both probe statuses use muted ink. The Windows input note uses the muted font and keeps the normal text color. Hosts scale them to the monitor DPI. |
| `internal/core/texttarget` | Win32 edit, rich edit, and WinForms edit classes, including password style, plus Chrome, Edge, Firefox, CEF, and Electron window classes. A renderer surface only authorizes a guarded paste probe. When a password probe cannot run, the whole browser or Electron window is treated as sensitive. |
| `internal/core/logfile` | Rotate a diagnostic log before it is opened: one active file up to 4 MiB and three numbered backups. Hosts choose the path and write the lines. macOS uses the same size, backup count, and rotation steps. |
| `internal/core/jsonl` | Voicebridge frame limits shared with the macOS client: protocol version 1, an 8 MiB frame, a 128-byte request ID, and 65536 retained request IDs. |
| `internal/core/session` | The active voice-task generation. Starting another generation cancels the previous context. Hosts still verify the editor target before writing. |
| `internal/core/history` | Current-session voice results in memory: at most 10 entries and 4 MiB, newest first, never a partial transcript. Menu text is the category and time only. Both hosts use the same empty, clear, and section titles. A missing history item says it was cleared. An empty error log says no error was recorded. Those two sentences stay different from the empty-session sentence. |
| `internal/core/update` | Compare the installed version with GitHub releases and produce the shared status text. A newer release that was found without an error asks to open the page. An error, a missing release, or the current release shows the summary instead. The Windows already-checking sentence is not the macOS checking sentence. Hosts display the result and open the releases page. The checker does not download installers. |
| `internal/core/clipboard` | Whether a captured clipboard may be restored, and how a synthetic copy retry spends its time budget. A snapshot refuses bitmap, palette, metafile, and owner-display formats before copying them, and refuses a block that is empty or past the per-format or total byte cap. A text read uses its own 8MB cap, separate from the JSONL frame limit. Opening the clipboard retries 20 times, 25ms apart. Restore failures that leave the original contents unchanged stay distinct from a failed text write. Hosts own the native pasteboard. |
| `internal/core/ux` | Fixed recovery text for known provider, ASR, and editor failures, the shared result-card titles, the copy and apply status lines, the rule that copy is primary only when the card cannot apply, the muted note, and the editor surface, the refusal to save settings during a voice task, the tray and pause sentences, and the password-field refusals for dictation, selection, and rewrite. Unknown errors stay with the host so private request data is not echoed. Owned sentences, including an empty transcript, a short recording, a password refusal, and a selection that is too long, are shown unchanged on both hosts. An unclassified macOS bridge failure keeps its ASR or model-failure prefix. macOS keeps the same title, copy-status, save-refusal, pause, and password strings. Windows save success still says shortcuts and devices take effect after restart; macOS keeps its own saved sentence. Dictation whose target window changed shows the not-inserted card and the fallback pill. A failed dictation paste shows the copy card and the fallback pill. A successful paste sets the success pill and no card. A spoken rewrite that is not pasted leaves the current pill and shows the result card. A dictation paste checks an empty transcript, a held shortcut, the target window, and a password field in that order, and stops at the first failure. The held-shortcut sentence is shared; the 2s and 2500ms waits stay separate. Selection replacement checks an expired task, a 3s modifier wait, the target window, and a password field before reading the clipboard. Its later window checks and clipboard-restore sentence stay different from dictation. |
| `internal/core/config` | Application settings schema and defaults, JSON parsing/serialization, normalization, API base-URL validation and credential-field transformation callbacks. Base URLs are trimmed http(s) addresses without userinfo, query, or fragment. Recording length is kept from 1 to 180 seconds and otherwise returned to 60. Meeting recognition is multipart or llama-prefix, listed in that settings order. API keys longer than 4000 bytes are rejected. A settings save keeps the current audio device unless the combo index is in range. No filesystem access or OS encryption implementation. |
| `internal/core/provider` | Safe HTTP clients, redirect blocking, bounded responses, model discovery, HTTP errors and reasoning-tag removal. |
| `internal/core/speech` | WAV/multipart ASR requests, transcript processing, chunking and request cancellation. |
| `internal/core/serviceprobe` | Shared ASR silent-WAV upload and LLM model-list connection probing for both desktop hosts, including the idle, running, and stale settings lines. |
| `internal/core/textedit` | Selected-text length/cancellation validation, spoken-command ASR-to-edit orchestration, intent classification and parsing, explicit-command write authorization, routing, plain-text rewrite and shared model completion transport. Both hosts refuse a selection over the rune limit with the same sentence before recording or sending it. A missing or non-positive limit uses the same 12000-rune default. |
| `internal/core/meeting` | Stream segmentation, adaptive ASR previews, session epochs/pause/resume/cancellation (`SessionRuntime`), bounded final/preview queues and revision-fenced caption translation (`Pipeline`), captions, replies, inference priorities, history and layout policies. Profile notes are limited to 4000 background runes and 2000 term runes before trimming. A reply refinement accepts one of the three suggestions and at most 2000 runes. The Windows refine field stops typing at 600. The refine button requires an owner and English text; the click still requires a typed instruction and does not require English. A spoken expression waits 50 seconds, keeps five finished turns, and stops on a microphone error before a short buffer. Its short-buffer and empty-recognition sentences stay different from dictation and rewrite. The live line “正在聆听 · 按住听写键说中文” is not the empty-status fallback “正在聆听”. Running meeting apps list Zoom first, then other titles case-insensitively. A paused app ignores a posted meeting start. A demo still starts, and suggestions run only for a live meeting. A demo does not own a hold. A canceled meeting hold drains the recorder, clears busy, idles the tray, and closes the pill. A live meeting hold expresses and leaves the tray and pill with that expression. A meeting profile text failure leaves the panel open and does not change the recognition mode. A recognition-mode failure leaves the panel open after the text has been saved. A paused meeting still updates the status line and button faces, and leaves captions, replies, and the expression unchanged. Following the latest turn clears the unread count even when the history text did not change. The expression copy button enables for a stored expression. Reply copy still requires a finished reply. Accepting suggestions from a click only checks that the meeting is not paused. The button also requires an owner and a pending reply. Both prefixes stay different from the copy failure. A posted pill phase applies only while that pill is still the current session. A posted hold release or timeout applies only while that hold is still recording. Stopping a hold routes a live meeting ahead of dictation, then a spoken rewrite, then toggle mode. Dictation and meeting show the processing pill; spoken rewrite shows the selection pill. Reply generation waits 30 seconds, stays quiet while capture is paused, and asks the user to wait when the latest turn is unfinished. An express-priority call uses the expression stage even in reply mode. The session pause line stays different from the HUD pause line. Meeting stays on Windows. Meeting button ids, actions, the next view flags, and the HUD status, button, reply, and history sentences live in this package. Toolbar widths, pane visibility, the reading and profile stacks, divider hit bands and marks, the logical drag distance, the minimum client size, reading font faces, the transcript bottom check, and the space reserved for chrome come from the same layout rules. Streaming panels share one repaint interval. Canceling meeting work drops an unfinished expression and replaces a visible status with “处理已取消”. A finished expression stays, and an empty status stays empty. The live caption uses the primary ink and the reading surface. Captions, both current languages, replies, the expression and its source, the instruction, and both profile fields share that reading surface. The live caption is not one of those fields. A minimized or maximized meeting window keeps its last normal rectangle. Closing a demo window quits that window; a live meeting asks its owner to stop. |

Core packages are built and tested without Win32, WASAPI, COM or native GUI
imports. The CI boundary check compares core source/test file sets and direct
platform API imports on Linux, Darwin and Windows. Linux runs race-enabled Go
tests; a real macOS runner executes core tests and compiles the core for Darwin
amd64 and arm64. Xcode CI also builds and tests the native macOS application on Apple Silicon and Intel runners. Hardware audio, Keychain and cross-app Accessibility permissions require physical-device verification.

## Native Windows integration

| Area | Implementation and ownership |
| --- | --- |
| Meeting audio | `meeting_capture_windows.go` owns WASAPI process-loopback activation, COM buffers, events and process lifetime. It validates native packets before passing PCM16 data to `audio.PCMConverter`. `meeting_windows.go` and `microphone_windows.go` retain host device integration. |
| Meeting coordinator | `meeting_session.go` constructs `meeting.Pipeline` and supplies inference, caption, metrics and HUD hooks. It retains host configuration snapshots, model scheduling, UI state and native presentation; `meeting_state.go` holds host view state. |
| Text selection and insertion | `task_worker_windows.go` invokes `textedit.ResolveSelectedTask` and `textedit.RouteTask`, and uses `session.Epoch` to cancel stale work. `clipboard_windows.go`, `uia_password_windows.go`, `unicode_input_windows.go`, `mouse_windows.go` and related Win32 code own foreground checks, clipboard restoration, guarded paste and input. Restoration is allowed only by `clipboard.MayRestore`. A synthetic copy waits 35ms, then 900ms for Ctrl/Alt/Shift, and stops with a different sentence when the editor leaves before the copy than when it leaves during the copy. A clipboard that never changes is not treated as a selection. A held-shortcut rewrite stops before copying when the foreground window already changed, and stops again when the copied selection belongs to another window. A manual apply waits 90ms after focusing the editor and stops when that editor has closed. Those three sentences stay distinct and still classify as a moved selection. |
| Windows UI | `meeting_hud_windows.go`, `settings_windows.go`, `popup_windows.go`, `result_direct2d_windows.go`, `tray_windows.go` and `handy_status_windows.go` render native controls. The recording pill reads its phases and geometry from `internal/core/indicator`. |
| Configuration and credentials | `config.go` exposes the shared settings model to the host. `config_store.go` owns user paths and private/atomic file operations; `secrets_windows.go` encrypts/decrypts credentials with Windows DPAPI. `secrets_other.go` is not a macOS Keychain adapter. |

## Meeting data flow

```text
Windows process selection and WASAPI capture
    -> core/audio PCM16 validation, channel mixing and 16 kHz framing
    -> core/meeting stream segmentation and adaptive audio turns
    -> core/meeting SessionRuntime and Pipeline (epochs, ASR priority, revisions)
    -> host inference hooks using core/speech, core/meeting and core/provider
    -> core/meeting caption, translation and reply state
    -> Windows native Meeting HUD
```

Selected text and meeting transcripts are untrusted model input. The HTTP
client rejects cross-host redirects, and configuration validates the chosen
API endpoints. Text replacement requires an explicit editing command and
passes the native foreground/selection guard. Windows credentials are stored
using the current user's DPAPI protection.

## Native macOS integration

`macos/VoiceRewrite.xcodeproj` builds the SwiftUI/AppKit host and bundles native Go `voicebridge`. The Helper calls the same `internal/core` packages as Windows; `probe_asr` and `probe_llm` expose identical service diagnostics. `internal/contract` is the settings catalog: page titles, control labels, order, which controls each host shows, and the Windows command for each settings button. `cmd/contractgen` writes the macOS indicator math, result copy, failure-status rule, session history, result-card frames, selection limit, side-button hold, endpoint defaults, base-URL check, and settings form from that catalog and the Go core. Per-frame pill drawing stays in the host. CI runs `go run ./cmd/contractgen -check` and fails when a generated file differs. ASR and text-edit failures use `ux.Classify`, so macOS shows the same recovery text as Windows when the failure is in the shared catalog. The `selected_voice_task` operation runs the same spoken-selection ASR + textedit orchestration used by Windows; macOS captures the physical microphone and validates the original Accessibility selection before attempting a result write. `Microphone` captures audio, `VoiceRewriteStorage` owns private settings and Keychain credentials, and `VoiceRewriteInteraction` owns Carbon shortcuts, guarded Accessibility insertion, and the follow-up for a finished dictation or selected-text task. That follow-up chooses the status, probe line, pill phase, history, and whether the host inserts, previews, or replaces. Dictation still starts the microphone when the target is missing or the caret capture fails. A stale token does not start it, and a microphone that starts after the token expires is canceled without showing the recording pill. A spoken selection capture cancels the task and skips the side-button release when the token is stale, even if the selection is also too long. A selection that is too long does not start the microphone and still releases the side button. A typed selection leaves processing set on a stale token, and a typed capture error does not cancel the Accessibility task. A stopped recording with a stale token sends no audio and leaves the probe lines unchanged. A failed stop on a stale token leaves processing set. A spoken selection sends the spoken task and sets the listening and waiting probe lines. Dictation sends transcribe and sets only the transcribing line. A transcribe status writes the ASR line, a selected-task status writes the LLM line, and a spoken selection writes both. A spoken selection is still not a settings probe. A busy voice-pause click is refused and leaves the pause flag unchanged. Resuming voice uses the idle sentence. A fresh side-mouse listener uses the listening sentence, or the paused sentence when voice is already paused. Restarting an existing listener leaves the status line alone. A macOS settings save reports a busy voice task before a long credential, and a long credential before an invalid shortcut plan. Those refusals keep the typed keys. A helper connection chooses the failed detail, service status, and whether both probes are cleared. A rejected handshake and a failed handshake stay different sentences. A missing bundle leaves the starting status unchanged. An update reply chooses the status and whether a release page is offered. A transport failure wins, a missing summary is replaced, and an empty summary stays empty. A successful insert or replacement does not open a card. A transport failure is decided before an empty or rejected model result. The host applies the follow-up. Swift handles the user interface, platform permissions and lifecycle. The macOS recording pill uses the same phases, labels, sizes and fade timing as Windows. AppKit owns the non-activating panel. The microphone starts only after the side-button hold, so a short navigation click does not open the input device.

macOS Meeting application-audio capture remains a separate integration requirement. Physical microphone, Keychain and Accessibility behavior plus distribution signing must be verified before public macOS release.
